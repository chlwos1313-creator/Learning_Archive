# 3과목: 데이터베이스 구축 핵심 요약

---

## 1. 데이터베이스 설계 및 스키마
### 데이터베이스 설계 단계
1.  **개념적 설계:** 개념 스키마 모델링, E-R 다이어그램 작성.
2.  **논리적 설계:** 목표 DBMS에 맞는 논리 구조로 매핑, **정규화** 수행.
3.  **물리적 설계:** 저장 레코드 형식, 접근 경로, **반정규화** 검토.

### 스키마 (Schema) 3계층
* **외부 스키마:** 사용자나 프로그래머 관점의 논리적 구조.
* **개념 스키마:** 기관 전체 관점의 통합 데이터베이스 구조 (보안, 접근 권한 등 정의).
* **내부 스키마:** 물리적 저장장치 관점의 구조.

## 2. 관계형 데이터베이스 (Relational DB)
### 주요 용어
* **튜플 (Tuple):** 행(Row), 레코드(Record). 수 = **기수(Cardinality)**.
* **속성 (Attribute):** 열(Column), 필드(Field). 수 = **차수(Degree)**.
* **도메인 (Domain):** 하나의 속성이 가질 수 있는 원자값들의 집합.

### 키 (Key)의 종류
* **후보키 (Candidate Key):** 유일성과 최소성을 모두 만족하는 키.
* **기본키 (Primary Key):** 후보키 중 선택된 키 (NULL 불가, 중복 불가).
* **대체키 (Alternate Key):** 후보키 중 기본키를 제외한 나머지.
* **슈퍼키 (Super Key):** 유일성은 만족하지만 최소성은 만족하지 못하는 키.
* **외래키 (Foreign Key):** 다른 릴레이션의 기본키를 참조하는 키.

### 무결성 (Integrity) 규정
* **개체 무결성:** 기본키는 NULL 값을 가질 수 없으며 중복될 수 없음.
* **참조 무결성:** 외래키 값은 참조하는 릴레이션의 기본키 값과 동일하거나 NULL이어야 함.
* **도메인 무결성:** 특정 속성 값은 정의된 도메인에 속한 값이어야 함.

## 3. 관계 대수 및 정규화
### 순수 관계 연산자
* **Select ($\sigma$):** 조건에 맞는 튜플 추출 (수평 연산).
* **Project ($\pi$):** 속성 리스트에서 제시된 속성만 추출 (수직 연산).
* **Join ($\bowtie$):** 두 릴레이션을 합쳐 새로운 릴레이션 형성.
* **Division ($\div$):** 속성 포함 관계를 이용한 연산.

### 정규화 (Normalization) 과정
1.  **1NF:** 모든 도메인이 **원자값**으로 구성.
2.  **2NF:** **부분 함수적 종속** 제거 (완전 함수적 종속 만족).
3.  **3NF:** **이행적 함수적 종속** 제거.
4.  **BCNF:** 결정자가 모두 **후보키**여야 함.
5.  **4NF:** **다치 종속** 제거.
6.  **5NF:** **조인 종속** 제거.

## 4. SQL (Structured Query Language)
### DDL (데이터 정의어)
* **CREATE:** SCHEMA, DOMAIN, TABLE, VIEW, INDEX 생성.
* **ALTER:** TABLE 구조 변경.
* **DROP:** 객체 삭제 (`CASCADE` / `RESTRICT` 옵션).

### DML (데이터 조작어)
* **SELECT:** 데이터 검색 (`GROUP BY`, `HAVING`, `ORDER BY`).
* **INSERT:** 데이터 삽입.
* **DELETE:** 데이터 삭제.
* **UPDATE:** 데이터 갱신.

### DCL (데이터 제어어)
* **GRANT / REVOKE:** 권한 부여 및 취소.
* **COMMIT:** 트랜잭션 성공적 종료 및 반영.
* **ROLLBACK:** 트랜잭션 실패 시 원 상태 복구.

## 5. 트랜잭션 및 병행 제어
### 트랜잭션의 특성 (ACID)
* **Atomicity (원자성):** 전부 수행되거나 전혀 수행되지 않아야 함 (All or Nothing).
* **Consistency (일관성):** 수행 후에도 DB 상태는 일관되어야 함.
* **Isolation (독립성/격리성):** 실행 중 다른 트랜잭션의 간섭을 받지 않음.
* **Durability (영속성):** 성공 결과는 영구적으로 반영됨.

### 회복(Recovery) 및 병행 제어
* **회복 기법:** 즉시 갱신, 지연 갱신, 검사점(Checkpoint), 그림자 페이지 기법.
* **병행 제어 기법:** 로킹(Locking), 타임 스탬프(Time Stamp), MVCC(다중 버전 동시성 제어).
* **로킹 단위:** 단위가 크면 관리는 쉽지만 병행성(공유도)은 낮아짐.
